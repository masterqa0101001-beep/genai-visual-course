4. The 10 Loop Engineering Design Patterns

Every autonomous AI system uses one or more of these patterns:

① Fix Loop

DETERMINISTIC

Goal: "Make all tests pass"
How: Run tests → see failures → fix code → run tests → repeat until green
Termination: All tests pass OR max 10 iterations
Example: Claude Code's /loop command for TDD

② Build Loop

NON-DETERMINISTIC

Goal: "Implement this feature spec"
How: Read spec → implement piece → validate → implement next piece → repeat
Termination: Spec fully implemented (needs evaluator)
Risk: Expensive if spec is vague

③ Refine Loop

YOUR QUALITY COUNCIL!

Goal: "Score ≥ 75/100 on quality"
How: Generate → evaluate → improve based on feedback → evaluate again
Termination: Score threshold met OR max attempts
YOUR CODE: ContentMind improvement loop (3 tries, escalating thresholds)

④ Monitor Loop

SCHEDULED

Goal: "Keep system healthy"
How: Check metrics → if degraded → act → recheck
Trigger: Runs on schedule (every hour/day)
YOUR CODE: GitHub Actions daily pipeline IS this pattern!

⑤ Review Loop

Goal: "PR has no issues"
How: Read code → identify issues → fix → verify fix → repeat for next issue
Termination: No more issues found
Example: Automated PR review + auto-fix

⑥ Multi-Agent Loop

Goal: Complex task requiring specialization
How: Planner breaks task → executors work in parallel → reviewer validates → planner adjusts
YOUR CODE: ContentMind 14-agent pipeline with routing

⑦ Feedback Loop

Goal: "Improve over time based on real results"
How: Observe outcomes → analyze what worked → adjust strategy → observe again
YOUR CODE: ContentMind Layer 7 (Analytics → Qdrant → weight calibration)

⑧ Guard Loop

Goal: "Continuously validate safety"
How: Monitor output → check against rules → block/flag if violation → continue
Example: Content moderation running on every output

⑨ Learning Loop

Goal: "Get better at task over iterations"
How: Attempt → fail → store failure reason → next attempt avoids same mistake
Emerging: Agents that maintain a "don't do this again" memory

⑩ Cascade Loop

Goal: "Solve by escalating complexity"
How: Try simple approach → if fails → try medium → if fails → try complex
YOUR CODE: TTS: Edge-TTS primary → backup voices → gTTS fallback

7. How to Design a Good Loop (The Principles)

Principle 1: Make goals VERIFIABLE (deterministic > non-deterministic)

"All tests pass" is verifiable. "Make it good" is not. The more measurable your goal, the more reliable your loop. YOUR threshold (score ≥ 75) is a perfect example — it's a number the system can check without human judgment.

Principle 2: Always set a budget (max iterations + max tokens)

A loop without limits is an open-ended bill. Peter Steinberger's team spent $1.3M/month in tokens. YOUR design is smarter: max 3 attempts with escalating acceptance thresholds (75→75→65). That's budget-conscious loop engineering.

Principle 3: Each iteration must make PROGRESS (no spinning)

If the agent retries the exact same action after the same error — that's spinning, not looping. Good loops include: escalating strategy (YOUR "be MORE aggressive" on attempt 2), memory of what was tried, and detection of repeated failures.

Principle 4: Design the EXIT before the ENTRY

Before writing a loop, answer: "How does this stop?" Success condition, failure condition, escalation path. YOUR code does this right — each loop has clear termination: score passes, max attempts reached, or fallback to best-so-far.

Principle 5: Manage context across iterations (memory)

Each iteration generates more context. Don't let it overflow. Strategies: summarize previous attempts, keep a "tried_approaches" list, prune irrelevant history. YOUR PipelineState TypedDict is context management across loop iterations.

9. Interview Answers — Loop Engineering

Q: "What is loop engineering and how have you applied it?"

"Loop engineering is designing autonomous systems where an agent iterates toward a goal without human intervention between steps. Instead of prompting manually, you define the trigger, goal, tools, feedback mechanism, and termination conditions — then the system runs itself. My ContentMind pipeline is a daily monitor loop with a nested refine loop: it generates content autonomously, evaluates via a quality council, and iterates with escalating thresholds (75→75→65) until quality passes or budget is exhausted. I was doing this before the term was coined in June 2026."

Q: "How do you prevent loops from running forever?"

"Five mechanisms: (1) Max iteration count — hard limit, always. (2) Token budget — stop if cost exceeds threshold. (3) Progress detection — if the same error repeats twice, escalate or stop, don't spin. (4) Escalating acceptance — lower the quality bar on later attempts so you don't chase perfection forever. (5) Timeout — wall-clock time limit regardless of iterations. My pipeline uses 1, 3, and 4. Adding 2 and 5 would make it production-hardened."

Q: "Loop engineering vs prompt engineering — what's the difference?"

"Prompt engineering optimizes a SINGLE interaction: one input → one output. Loop engineering designs the SYSTEM around interactions: triggers that start the agent, goals that define success, feedback mechanisms that evaluate progress, and termination logic that decides when to stop or escalate. The prompt is one component INSIDE the loop. The loop is the orchestration layer that makes the whole thing autonomous."
