Part 1: FastAPI Fundamentals

What is FastAPI?

Python web framework for building APIs. It's fast (async), auto-generates docs, and uses type hints for validation. It's what Flask wished it was.

# Install
pip install fastapi uvicorn pydantic

# app.py — Your first API
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI(title="Gen AI RAG API")

class QueryRequest(BaseModel):
    question: str
    top_k: int = 3

class QueryResponse(BaseModel):
    answer: str
    sources: list[str]
    confidence: float

@app.post("/query", response_model=QueryResponse)
async def query_documents(req: QueryRequest):
    # Your RAG logic goes here
    return QueryResponse(
        answer="FastAPI is a modern Python web framework",
        sources=["doc1.pdf", "doc2.pdf"],
        confidence=0.92
    )

@app.get("/health")
async def health_check():
    return {"status": "healthy", "version": "1.0.0"}

# Run: uvicorn app:app --reload --port 8000
# Docs auto-generated at: http://localhost:8000/docs
Key Insight: FastAPI auto-generates interactive API docs (Swagger UI) at /docs. Interviewers love seeing this — it shows "production-ready" thinking.

Adding RAG to the API

from sentence_transformers import SentenceTransformer
from qdrant_client import QdrantClient
from groq import Groq

# Initialize (do this ONCE at startup, not per request)
embed_model = SentenceTransformer("all-MiniLM-L6-v2")
qdrant = QdrantClient(url="http://localhost:6333")
llm = Groq()

@app.post("/query", response_model=QueryResponse)
async def query_documents(req: QueryRequest):
    # 1. Embed the question
    query_vector = embed_model.encode(req.question).tolist()
    
    # 2. Search Qdrant
    results = qdrant.search(
        collection_name="documents",
        query_vector=query_vector,
        limit=req.top_k
    )
    
    # 3. Build context from retrieved chunks
    context = "\n".join([r.payload["text"] for r in results])
    sources = [r.payload["source"] for r in results]
    
    # 4. Generate answer with LLM
    response = llm.chat.completions.create(
        model="llama-3.3-70b-versatile",
        messages=[
            {"role": "system", "content": "Answer based on context only. If unsure, say so."},
            {"role": "user", "content": f"Context:\n{context}\n\nQuestion: {req.question}"}
        ],
        temperature=0.3
    )
    
    return QueryResponse(
        answer=response.choices[0].message.content,
        sources=sources,
        confidence=results[0].score if results else 0.0
    )

Adding Streaming Responses (SSE)

from fastapi.responses import StreamingResponse

@app.post("/query/stream")
async def query_stream(req: QueryRequest):
    async def generate():
        # Same retrieval as above...
        stream = llm.chat.completions.create(
            model="llama-3.3-70b-versatile",
            messages=[...],
            stream=True  # Enable streaming
        )
        for chunk in stream:
            if chunk.choices[0].delta.content:
                yield f"data: {chunk.choices[0].delta.content}\n\n"
        yield "data: [DONE]\n\n"
    
    return StreamingResponse(generate(), media_type="text/event-stream")

Part 2: Docker — Containerize Everything

Why Docker?

"Works on my machine" is not production. Docker packages your app + dependencies into a portable container that runs identically everywhere.

Without Docker: With Docker: "pip install broke" "docker run" → works "Python version wrong" Same environment everywhere "Missing system library" Deploy to any cloud "Works on my machine" Reproducible builds

Dockerfile

# Dockerfile
FROM python:3.11-slim

WORKDIR /app

# Install dependencies first (cached layer)
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Copy application code
COPY . .

# Expose port
EXPOSE 8000

# Health check
HEALTHCHECK --interval=30s --timeout=3s \
  CMD curl -f http://localhost:8000/health || exit 1

# Run with uvicorn
CMD ["uvicorn", "app:app", "--host", "0.0.0.0", "--port", "8000"]

Docker Compose (app + Qdrant together)

# docker-compose.yml
version: '3.8'
services:
  qdrant:
    image: qdrant/qdrant:latest
    ports:
      - "6333:6333"
    volumes:
      - qdrant_data:/qdrant/storage

  rag-api:
    build: .
    ports:
      - "8000:8000"
    environment:
      - GROQ_API_KEY=${GROQ_API_KEY}
      - QDRANT_URL=http://qdrant:6333
    depends_on:
      - qdrant

volumes:
  qdrant_data:

# Build and run everything:
docker-compose up --build

# Your API: http://localhost:8000
# Qdrant: http://localhost:6333
# Swagger docs: http://localhost:8000/docs

# Step 2: Deploy to Cloud Run

  --image gcr.io/YOUR_PROJECT/rag-api \
  --platform managed \
  --region asia-south1 \
  --allow-unauthenticated \
  --set-env-vars GROQ_API_KEY=your-key

Error Handling

from fastapi import HTTPException

@app.post("/query")
async def query_documents(req: QueryRequest):
    try:
        # ... RAG logic
    except RateLimitError:
        raise HTTPException(status_code=429, detail="LLM rate limit. Retry in 60s.")
    except Exception as e:
        raise HTTPException(status_code=500, detail=f"Internal error: {str(e)}")

Middleware (logging, CORS, timing)

import time
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(CORSMiddleware, allow_origins=["*"], allow_methods=["*"])

@app.middleware("http")
async def add_timing(request, call_next):
    start = time.time()
    response = await call_next(request)
    response.headers["X-Process-Time"] = str(time.time() - start)
    return response

Interview Questions on This Topic

Q: "How would you deploy an LLM application to production?"
A: "I'd containerize it with Docker (reproducible builds), serve via FastAPI (async, auto-docs, type-safe), and deploy to a managed platform like Cloud Run or ECS. Key additions: health checks, rate limiting, CORS, structured logging, and environment-based config. I'd add a CI/CD pipeline that runs evaluation tests before deploying."
Q: "What's the difference between sync and async in FastAPI?"
A: "Async (await) allows handling multiple concurrent requests without blocking. Critical for LLM apps because API calls take 1-5 seconds. With sync, one slow LLM call blocks all other users. With async, the server handles other requests while waiting for the LLM response."
Q: "How do you handle secrets in Docker?"
A: "Never bake secrets into images. Use environment variables (--set-env-vars in Cloud Run), or secret managers (AWS Secrets Manager, GCP Secret Manager). In docker-compose, use .env files (gitignored). In K8s, use Secrets objects."
