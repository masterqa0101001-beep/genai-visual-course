PART C — AGENTIC SECURITY (OWASP Top 10 for Agentic Apps 2026)

⭐ THE NEW FRONTIER

OWASP shipped a separate Top 10 for Agentic Applications in 2026 (ASI-prefixed) because agents introduce risks the LLM list didn't cover — risks from autonomous action, not just model output. Almost no candidate knows this list. Knowing it is a flex.

3. The agentic risks (autonomy-specific)

RiskMeaningDefense
!Goal hijackingAttacker redirects the agent's objective mid-taskvalidate goals; trust boundary; monitor goal drift
!Tool misuseAgent uses a legit tool in a harmful wayconstrain tool args; approval for high-impact calls
!Privilege abuseAgent escalates / uses perms beyond its taskper-agent identity + scoped RBAC (Entra Agent ID)
!Memory poisoningInjected content in long-term memory steers future runsvalidate memory writes; provenance; isolation
!Rogue / cascading agentsOne compromised agent corrupts others in a multi-agent systemisolate agents; validate handoffs; audit trail
!Identity & authAgents acting without proper identity/attributiongive each agent an identity; log who did what
The through-line: P0 security was about the model (injection, output). Agentic security is about autonomous action — identity, permissions, memory integrity, and multi-agent blast radius. Both lists matter; name both in interviews.
YOUR work: your chaos module now tests prompt injection (S13). The next portfolio move: a "rogue agent" or "memory poisoning" scenario — testing that one compromised node can't corrupt the multi-agent pipeline. That's cutting-edge.

4. The production security checklist

  1. Each agent has its own scoped identity (least privilege per agent)
  2. High-impact tool calls go through a human-in-the-loop gate
  3. All actions are audited (who/what/when) — no anonymous autonomy
  4. Long-term memory writes are validated + provenance-tracked
  5. Multi-agent handoffs validate state (contain blast radius)
  6. Secrets in a vault, never in prompts/logs/code
  7. A spend cap + rate limits (unbounded consumption / denial of wallet)

5. Founder Q&A Drills

How do you keep agent costs under control at scale?
Model routing (cheap model for easy steps, strong for hard), prompt + semantic caching, token budgeting via history summarization, batching independent calls, and preferring workflows over agents where flexibility isn't needed. Then measure real per-task cost and quality, not estimates.
What breaks when you deploy an agent to production?
Long runs exceed HTTP timeouts (use async/queues), state isn't resumable across pods (externalize to Redis/Postgres), and prompt changes regress quality (gate deploys on the eval suite). Plus health checks and graceful degradation.
How is agentic security different from LLM security?
LLM security (OWASP 2025) is about model output — injection, data leakage, output handling. Agentic security (OWASP 2026, ASI) is about autonomous action — goal hijacking, tool misuse, privilege abuse, memory poisoning, rogue/cascading agents, and agent identity. Agents can act, so permissions and auditing become first-class.
A compromised agent in a multi-agent system — how do you contain it?
Per-agent scoped identity (least privilege), validated handoffs so bad state can't propagate, agent isolation, a full audit trail, and human gates on high-impact actions. The goal is bounding blast radius so one rogue agent can't corrupt the system.
