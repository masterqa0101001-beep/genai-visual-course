The Big Picture: When to Fine-Tune vs RAG vs Prompt Engineering

ApproachChangesBest ForCost
Prompt EngineeringNothing (just instructions)Behavior tweaks, format controlFree
RAGAdds external knowledgeCurrent data, citations, domain factsLow (embedding + storage)
Fine-tuningChanges model weightsStyle, domain language, new tasksMedium (GPU hours)
Pre-trainingTrains from scratchNew language, entirely new domainVery High ($M+)
Decision Framework: Try prompt engineering first → if not enough, try RAG → if model doesn't "speak your domain" or needs a specific behavior pattern, fine-tune → only pre-train if nothing else works.

What is LoRA?

The Problem

A 7B parameter model has 7 billion weights. Full fine-tuning means updating ALL of them. That needs 28GB+ GPU RAM (FP32) or 14GB+ (FP16). Expensive and slow.

The LoRA Solution

Instead of updating the full weight matrix W (size d×d), add a small trainable "adapter" beside it: ΔW = A × B where A is (d×r) and B is (r×d), and r is tiny (4-64).

Full Fine-Tuning: LoRA: ┌─────────────┐ ┌─────────────┐ ┌───┐ │ W (7B) │ ← update │ W (7B) │ │ A │ (d×r) │ ALL │ ALL params │ FROZEN │ + │ │ │ params │ │ ❄️ │ └─┬─┘ └─────────────┘ └─────────────┘ │ ↓ Training: 7B params ┌───┐ output Memory: 28GB+ │ B │ (r×d) Time: hours └───┘ Training: ~0.1% params (r=16 → ~4M) Memory: ~8GB (4-bit) Time: minutes on Colab T4

Intuition

Think of it like this: the pre-trained model already knows language. You just need to "steer" it slightly toward your domain. LoRA adds small "steering wheels" to specific layers without touching the main engine.

What is QLoRA?

QLoRA = Quantized LoRA. The base model is compressed to 4-bit precision (QLoRA) while the adapter matrices stay in 16-bit (for training stability).

MethodBase ModelAdaptersMemory (7B model)
Full fine-tuningFP16N/A (update all)~28GB
LoRAFP16 (frozen)FP16 (small)~16GB
QLoRA4-bit (frozen)FP16 (small)~6-8GB ✅ Colab T4!
Why QLoRA matters for you: Google Colab free tier gives you a T4 GPU (16GB VRAM). QLoRA lets you fine-tune a 7B model on it. No paid GPU needed.

Step 2: Load Model in 4-bit

import torch
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig

model_name = "meta-llama/Llama-3.1-8B-Instruct"

# 4-bit quantization config
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",           # NormalFloat4 — best quality
    bnb_4bit_compute_dtype=torch.float16, # Compute in FP16
    bnb_4bit_use_double_quant=True        # Quantize the quantization constants too
)

# Load model (will be ~4GB instead of 16GB)
model = AutoModelForCausalLM.from_pretrained(
    model_name,
    quantization_config=bnb_config,
    device_map="auto"
)
tokenizer = AutoTokenizer.from_pretrained(model_name)
tokenizer.pad_token = tokenizer.eos_token

Step 3: Configure LoRA

from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training

# Prepare model for training (freeze + enable gradient checkpointing)
model = prepare_model_for_kbit_training(model)

# LoRA configuration
lora_config = LoraConfig(
    r=16,                    # Rank — higher = more capacity, more memory
    lora_alpha=32,           # Scaling factor (usually 2×r)
    target_modules=[         # Which layers to add adapters to
        "q_proj", "k_proj", "v_proj", "o_proj",  # Attention
        "gate_proj", "up_proj", "down_proj"       # FFN
    ],
    lora_dropout=0.05,       # Regularization
    bias="none",
    task_type="CAUSAL_LM"
)

# Apply LoRA to model
model = get_peft_model(model, lora_config)
model.print_trainable_parameters()
# Output: trainable params: 3,407,872 || all params: 8,030,000,000 || trainable%: 0.04%

Step 4: Prepare Training Data

from datasets import Dataset

# Your training data — instruction/input/output format
training_data = [
    {
        "instruction": "Score this YouTube script for quality",
        "input": "Top 5 AI tools that will blow your mind in 2026...",
        "output": '{"critic": 6, "virality": 7, "seo": 5, "total": 62, "feedback": "Hook is weak. Add a specific claim in first sentence."}'
    },
    {
        "instruction": "Score this YouTube script for quality",
        "input": "In 2024, a single line of code deleted 1.2 billion user records...",
        "output": '{"critic": 9, "virality": 9, "seo": 7, "total": 88, "feedback": "Excellent hook. Specific, creates curiosity, stakes are clear."}'
    },
    # ... 500+ examples
]

def format_prompt(example):
    """Format into chat template."""
    text = f"""### Instruction: {example['instruction']}

### Input: {example['input']}

### Response: {example['output']}"""
    return {"text": text}

dataset = Dataset.from_list(training_data)
dataset = dataset.map(format_prompt)

Step 5: Train!

from trl import SFTTrainer
from transformers import TrainingArguments

training_args = TrainingArguments(
    output_dir="./results",
    num_train_epochs=3,
    per_device_train_batch_size=4,
    gradient_accumulation_steps=4,     # Effective batch = 16
    learning_rate=2e-4,
    warmup_steps=10,
    logging_steps=10,
    save_strategy="epoch",
    fp16=True,                         # Mixed precision
    optim="paged_adamw_8bit",          # Memory-efficient optimizer
    report_to="none"
)

trainer = SFTTrainer(
    model=model,
    train_dataset=dataset,
    args=training_args,
    tokenizer=tokenizer,
    dataset_text_field="text",
    max_seq_length=512,
    packing=True                       # Pack multiple examples per sequence
)

# GO!
trainer.train()
# ~20-40 minutes on Colab T4 for 500 examples × 3 epochs

Step 7: Inference with Fine-Tuned Model

from peft import PeftModel

# Load base model + LoRA adapter
base_model = AutoModelForCausalLM.from_pretrained(model_name, quantization_config=bnb_config, device_map="auto")
model = PeftModel.from_pretrained(base_model, "hemanth/content-scorer-lora")

# Generate
prompt = "### Instruction: Score this YouTube script for quality\n\n### Input: The future of AI is here and it's amazing...\n\n### Response:"
inputs = tokenizer(prompt, return_tensors="pt").to(model.device)
outputs = model.generate(**inputs, max_new_tokens=200, temperature=0.3)
print(tokenizer.decode(outputs[0], skip_special_tokens=True))

Key Concepts for Interviews

Q: "Explain LoRA. Why does it work?"
A: "LoRA exploits the fact that weight updates during fine-tuning have low intrinsic rank — meaning the 'change' needed to adapt a model is much smaller than the model itself. We decompose this change into two small matrices (A and B) with rank r. Instead of updating 7B parameters, we train ~4M. This gives 90-95% of full fine-tuning quality at a fraction of the cost."
Q: "What is r (rank) in LoRA? How do you choose it?"
A: "r controls the capacity of the adapter. Higher r = more expressiveness but more memory. Typical values: r=8 for simple tasks (classification), r=16 for medium (instruction following), r=64 for complex (domain adaptation). Start with r=16, increase if training loss plateaus."
Q: "What's the difference between LoRA and full fine-tuning quality?"
A: "For most tasks, LoRA achieves 95%+ of full fine-tuning performance. The gap widens only when: (1) the task is extremely different from pre-training, (2) you have millions of examples, or (3) you need to change very deep behavior. For instruction tuning and domain adaptation, LoRA is practically equivalent."
Q: "Which layers should you apply LoRA to?"
A: "Attention layers (q_proj, v_proj) are the minimum and work well for most tasks. Adding k_proj, o_proj, and FFN layers (gate_proj, up_proj, down_proj) improves quality marginally but costs more memory. I typically target all attention + FFN for best results on Colab T4."
Common Mistake: Don't fine-tune on too few examples (<100) or your model will overfit and produce gibberish on unseen inputs. 500-5000 high-quality examples is the sweet spot.
