Part 1: Azure OpenAI Service

Why Azure OpenAI (not raw OpenAI)?

Enterprise clients (Infosys's customers) use Azure because: data residency guarantees, VNet private access, Microsoft compliance certifications, Active Directory integration, and content filtering built-in. Same GPT-4 models, enterprise wrapper.

# pip install openai

from openai import AzureOpenAI

client = AzureOpenAI(
    api_key="your-azure-key",
    api_version="2024-06-01",
    azure_endpoint="https://your-resource.openai.azure.com/"
)

# Exactly the same as OpenAI — just different client initialization
response = client.chat.completions.create(
    model="gpt-4o-mini",  # This is your DEPLOYMENT name, not model name
    messages=[
        {"role": "system", "content": "You are a helpful assistant."},
        {"role": "user", "content": "Explain RAG in one sentence."}
    ],
    temperature=0.3
)
print(response.choices[0].message.content)
Key difference: In Azure, you deploy a model and give it a deployment NAME. You call the deployment name, not the model name. So model="my-gpt4-deployment" not model="gpt-4o".

Part 2: Semantic Kernel (Microsoft's LLM Framework)

Infosys's JD explicitly mentions Semantic Kernel. It's Microsoft's alternative to LangChain — tighter Azure integration, enterprise-focused.

LangChain vs Semantic Kernel: LangChain Semantic Kernel ├── Chains ├── Plugins (functions) ├── Agents ├── Planner (auto-orchestration) ├── Tools ├── Connectors (Azure, OpenAI) ├── Memory ├── Memory (semantic + chat) └── Python-first └── C# + Python + Java Key difference: SK uses "plugins" (collections of functions) that the AI can discover and call. LangChain uses "tools." Same concept, different terminology. 
# pip install semantic-kernel

import semantic_kernel as sk
from semantic_kernel.connectors.ai.open_ai import AzureChatCompletion

# Initialize kernel
kernel = sk.Kernel()

# Add Azure OpenAI service
kernel.add_service(AzureChatCompletion(
    deployment_name="gpt-4o-mini",
    endpoint="https://your-resource.openai.azure.com/",
    api_key="your-key"
))

# Define a plugin (function the AI can use)
from semantic_kernel.functions import kernel_function

class DocumentPlugin:
    @kernel_function(description="Search documents for relevant information")
    def search_docs(self, query: str) -> str:
        # Your RAG retrieval logic here
        return f"Found: relevant content for '{query}'"

# Register plugin
kernel.add_plugin(DocumentPlugin(), "documents")

# Chat with function calling
result = await kernel.invoke_prompt(
    "Find information about refund policy",
    settings={"function_choice_behavior": "auto"}
)
Q: "What's Semantic Kernel and how does it compare to LangChain?"
A: "Semantic Kernel is Microsoft's LLM orchestration framework — it's to Azure what LangChain is to the broader ecosystem. The key difference: SK uses 'plugins' (grouped functions) that the AI auto-discovers and calls, while LangChain uses 'tools' and explicit chains. SK has tighter Azure integration (native Azure AI Search, Cosmos DB connectors) and supports C#/Java in addition to Python. For Azure-heavy enterprises, SK is the natural choice. For flexibility across providers, LangChain/LangGraph."

Part 3: LLM Evaluation with RAGAS

Why Evaluation Matters

"How do you know your RAG is working?" Without metrics, you're guessing. RAGAS gives you standardized scores.

RAG Evaluation Metrics: ┌─────────────────────────────────────────────────────┐ │ RAGAS Metrics │ ├──────────────┬──────────────┬───────────────────────┤ │ Faithfulness │ Relevancy │ Context Precision │ │ │ │ │ │ "Is answer │ "Does answer │ "Are the retrieved │ │ grounded in │ address the │ chunks actually │ │ the context?"│ question?" │ relevant?" │ │ │ │ │ │ Detects: │ Detects: │ Detects: │ │ Hallucination│ Off-topic │ Bad retrieval │ └──────────────┴──────────────┴───────────────────────┘ 
# pip install ragas datasets

from ragas import evaluate
from ragas.metrics import (
    faithfulness,
    answer_relevancy,
    context_precision,
    context_recall
)
from datasets import Dataset

# Prepare evaluation dataset
eval_data = {
    "question": [
        "What is our refund policy?",
        "How do I reset my password?",
    ],
    "answer": [
        "You can get a full refund within 30 days of purchase.",
        "Click 'Forgot Password' on the login page.",
    ],
    "contexts": [
        ["Our refund policy allows returns within 30 days. Full refund for unused items."],
        ["To reset password: go to login page, click 'Forgot Password', enter email."],
    ],
    "ground_truth": [
        "Full refund available within 30 days for unused items.",
        "Go to login page and click Forgot Password.",
    ]
}

dataset = Dataset.from_dict(eval_data)

# Run evaluation
results = evaluate(
    dataset=dataset,
    metrics=[faithfulness, answer_relevancy, context_precision, context_recall]
)

print(results)
# {'faithfulness': 0.92, 'answer_relevancy': 0.88, 'context_precision': 0.85, 'context_recall': 0.90}

Hybrid Search (BM25 + Semantic)

# Using rank_bm25 for keyword scoring
from rank_bm25 import BM25Okapi
import numpy as np

# BM25 keyword scoring
tokenized_docs = [doc.split() for doc in documents]
bm25 = BM25Okapi(tokenized_docs)
bm25_scores = bm25.get_scores(query.split())

# Semantic scoring (from vector DB)
semantic_scores = [r.score for r in qdrant_results]

# Combine with Reciprocal Rank Fusion (RRF)
def reciprocal_rank_fusion(rankings: list[list], k=60):
    """Combine multiple rankings into one."""
    scores = {}
    for ranking in rankings:
        for rank, doc_id in enumerate(ranking):
            scores[doc_id] = scores.get(doc_id, 0) + 1 / (rank + k)
    return sorted(scores.items(), key=lambda x: x[1], reverse=True)

# Get top docs from each method, then fuse
bm25_ranking = np.argsort(bm25_scores)[::-1][:20]
semantic_ranking = [r.id for r in qdrant_results[:20]]
fused = reciprocal_rank_fusion([bm25_ranking.tolist(), semantic_ranking])

Agentic RAG (Decide HOW to retrieve)

Basic RAG: Query → Retrieve → Generate (one shot) Agentic RAG: Query → Agent DECIDES: ├── "I need more context" → retrieve again with different query ├── "This chunk is unclear" → retrieve parent document ├── "I need recent data" → call web search tool └── "I have enough" → generate answer 
# Agentic RAG with LangGraph
from langgraph.graph import StateGraph

def should_retrieve_more(state):
    """Agent decides if it needs more context."""
    if state["confidence"] < 0.7:
        return "retrieve_more"
    return "generate"

graph = StateGraph(RAGState)
graph.add_node("retrieve", retrieve_node)

graph.add_edge("retrieve", "evaluate_context")
graph.add_conditional_edges("evaluate_context", should_retrieve_more)
graph.add_edge("retrieve_more", "evaluate_context")  # Loop!
graph.add_edge("generate", END)

Graph RAG (Knowledge Graph + Vector Search)

Traditional RAG: Query → flat chunk retrieval → answer Graph RAG: Query → extract entities → traverse knowledge graph → find connected concepts → retrieve related chunks → richer context → better answer Example: "What's the relationship between Project X and Client Y?" - Flat RAG: might miss the connection (different documents) - Graph RAG: follows edges Project X → Team A → Client Y 
# Simplified Graph RAG concept
from neo4j import GraphDatabase

def graph_enhanced_retrieval(query: str):
    # 1. Extract entities from query
    entities = extract_entities(query)  # LLM call: "Project X", "Client Y"
    
    # 2. Query knowledge graph for connections
    with driver.session() as session:
        result = session.run("""
            MATCH path = (a)-[*1..3]-(b)
            WHERE a.name IN $entities OR b.name IN $entities
            RETURN path
        """, entities=entities)
    
    # 3. Get related document chunks
    related_chunks = get_chunks_for_entities(result)
    
    # 4. Combine with vector search results
    vector_chunks = semantic_search(query)
    all_context = related_chunks + vector_chunks
    
    # 5. Generate with enriched context
    return generate_answer(query, all_context)

Interview Questions

Q: "How do you evaluate a RAG system in production?"
A: "I use RAGAS with 4 metrics: Faithfulness (is the answer grounded in context — detects hallucination), Answer Relevancy (does it address the question), Context Precision (are retrieved chunks relevant), Context Recall (did we find all needed info). I maintain a golden test set of 50-100 query-answer pairs and run evaluation in CI/CD — any PR that drops metrics below threshold gets blocked."
Q: "When does semantic search fail and what do you do?"
A: "Semantic fails on: exact identifiers (error codes, IDs), acronyms the embedding model hasn't seen, numbers/dates, and rare proper nouns. Solution: hybrid search (BM25 for keywords + vector for meaning). Combine with Reciprocal Rank Fusion. This improves retrieval quality by 15-20% on enterprise documents."
Q: "What is Responsible AI and how do you implement it?"
A: "Responsible AI means: no harmful outputs, no bias, no PII leakage, full auditability. I implement with: NeMo Guardrails (input/output filtering), content safety classifiers, PII detection before and after LLM, confidence scoring (low confidence → human review), and comprehensive logging of all LLM interactions for audit."
