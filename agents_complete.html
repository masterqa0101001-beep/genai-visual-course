1. What is an AI Agent?

👨‍🍳 School Kid Analogy: A Chef With a Recipe Book

A normal LLM = someone who answers ONE question and stops. Like asking a friend: "What should I cook?" → "Pasta!" Done.

An Agent = a CHEF who: thinks what to cook → checks the fridge (tool) → finds a recipe (tool) → cooks step by step → tastes and adjusts → serves the dish.

Key difference: Agents take MULTIPLE ACTIONS and DECIDE what to do next based on results.

2. The Core Loop — ReAct (Reasoning + Acting)

EVERY agent framework (LangChain, LangGraph, CrewAI, AutoGen) is just this loop with more abstractions:

# The ENTIRE agent in pseudocode (this IS the loop):
while not done:
  thought = LLM(history + tools_description)  # THINK
  action = parse(thought)                    # DECIDE
  if action == "done": return answer      # DONE?
  result = execute_tool(action)             # ACT
  history.append(result)                    # OBSERVE

3. The 4 Agent Architectures (Cover 95% of Use Cases)

① ReAct (Single Agent + Tools)

MOST COMMON

COMPLEX TASKS

③ Multi-Agent Debate

YOUR COUNCIL

④ Supervisor (Router)

YOUR ROUTER

A supervisor decides WHICH worker agent to call based on the task. Your content_router.py (story vs tech mode) is exactly this.

4. Tool Calling — How Agents Use Tools

📱 Analogy: A Person With a Smartphone

You (the brain) DECIDE to check the weather. You open the weather APP (tool). You READ the result. You DECIDE what to wear based on that.

An agent does the same: DECIDES which tool to use → CALLS it → READS the result → DECIDES next action.

❌ Old Way: Text Parsing

LLM outputs: "ACTION: search\nINPUT: AI jobs"
# You parse this with regex (fragile!)
action = re.search(r'ACTION: (\w+)', text)

Breaks if LLM formats differently.

✅ New Way: Function Calling API

# LLM returns STRUCTURED JSON:
{"tool": "search", "args": {"query": "AI jobs"}}
# No parsing needed! Type-safe.

Built into OpenAI, Groq, Anthropic APIs.

7. Agent Failure Modes

💀 Infinite Loop — Agent keeps calling the same tool forever

Cause: LLM doesn't recognize the goal is achieved, or tool returns unhelpful results.

Fix: Max step limit (your pipeline uses this). Also: detect repeated actions and force termination.

💀 Wrong Tool Selected — Agent calls "search" when it should "score"

Cause: Tool descriptions are ambiguous or too similar.

Fix: Better tool descriptions. Add few-shot examples of correct tool use in system prompt.

💀 Hallucinated Tool — Agent tries to call a tool that doesn't exist

Cause: Text-parsing agents can invent tool names. LLM "imagines" tools.

Fix: Use function calling API (enforces valid tool names). Or validate against TOOLS dict before execution.

💀 Context Overflow — Too many observations fill the context window

Cause: Each loop iteration adds messages. After 10 steps, context is full.

Fix: Summarize history periodically. Keep only last 3 observations + summary of earlier ones.

💀 Cascading Errors — One bad tool result derails everything

Cause: Tool returns error, agent doesn't know how to recover.

Fix: Your approach: fallback chains (TTS: primary → 3 backups → gTTS). Also: let agent "skip" failed tools.

10. Interview Answers

Q: "How does an agent work under the hood?"

"An agent is a Think→Act→Observe loop. The LLM reasons about the task, selects a tool via function calling, executes it, observes the result, and loops until the goal is met or max steps reached. I can build one in 40 lines without any framework — frameworks add state management, error handling, and routing on top of this core loop."

Q: "When would you use multi-agent vs single agent?"

"Single agent with multiple tools for straightforward tasks (search + score + apply). Multi-agent when you need OPPOSING perspectives — like my quality council where a critic, fact-checker, and virality scorer evaluate the same content from different angles. The debate structure catches blind spots a single agent misses."

Q: "What is MCP and why does it matter?"

"MCP standardizes how LLMs discover and call external tools — like REST APIs but for AI agents. Instead of custom integrations per model, you build one MCP server and ANY MCP-compatible client (Claude, Kiro, Cursor) can use your tools. I built an MCP server for job search that exposes search, scoring, and reporting as structured tools. It's adopted by OpenAI, Google, Microsoft — 97M monthly SDK downloads."
