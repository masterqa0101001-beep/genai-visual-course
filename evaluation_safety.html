2. Metrics Deep Dive — The Complete Taxonomy

Every LLM metric is built from three primitives: Reference comparison (compare to gold answer), Property assertion (check structural properties), and Judge scoring (another LLM rates quality).

3. LLM-as-Judge — The 2026 Standard

Using a strong LLM to evaluate a weaker LLM's output. Research shows 81% correlation with human judgment (comparable to inter-annotator agreement). This is the dominant evaluation paradigm in production today.

# LLM-as-Judge Implementation with DeepEval (Python) from deepeval import assert_test from deepeval.metrics import FaithfulnessMetric, HallucinationMetric, GEval from deepeval.test_case import LLMTestCase # Custom rubric-based judge (most flexible pattern) correctness_metric = GEval( name="Correctness", criteria="Determine if the output is factually correct and complete", evaluation_params=[ LLMTestCaseParams.ACTUAL_OUTPUT, LLMTestCaseParams.EXPECTED_OUTPUT ], threshold=0.7 # Minimum passing score ) # Faithfulness: is EVERY claim grounded in context? faithfulness = FaithfulnessMetric(threshold=0.9) # Test case with all required components test_case = LLMTestCase( input="What is RAG?", actual_output=model_response, expected_output="RAG combines retrieval with generation...", retrieval_context=[chunk_1, chunk_2, chunk_3] ) # Run evaluation — fails CI if below threshold assert_test(test_case, [correctness_metric, faithfulness])

💡 Known Biases in LLM-as-Judge (Interview Gold)

Position Bias: Judges prefer the first response in pairwise comparisons. Fix: run twice with positions swapped.

Verbosity Bias: Longer answers get higher scores even when less accurate. Fix: add "conciseness" to rubric.

Self-Preference: GPT-4 rates GPT-4 outputs higher than Claude, and vice versa. Fix: use cross-model panels.

Sycophancy: Judges agree with the user's implied preference. Fix: remove opinion signals from judge prompt.

4. RAG Evaluation — The RAG Triad & Beyond

RAG has TWO failure modes that look identical from outside: bad retrieval (right answer never reached the LLM) and bad generation (context was correct but LLM ignored/hallucinated). RAG eval scores EACH LAYER separately so failures localize.

# Complete RAG Evaluation Pipeline with RAGAS from ragas import evaluate from ragas.metrics import ( faithfulness, answer_relevancy, context_precision, context_recall, context_entity_recall, answer_correctness ) from datasets import Dataset # Your golden evaluation dataset eval_data = { "question": ["What is attention?", "Explain RLHF"], "answer": [model_answer_1, model_answer_2], "contexts": [[chunk_1a, chunk_1b], [chunk_2a, chunk_2b]], "ground_truth": ["Attention computes...", "RLHF trains..."] } result = evaluate( Dataset.from_dict(eval_data), metrics=[faithfulness, answer_relevancy, context_precision, context_recall] ) # CI/CD Gate: block deploy if below thresholds assert result["faithfulness"] > 0.9, "Hallucination risk too high!" assert result["context_precision"] > 0.8, "Retriever bringing noise!" assert result["answer_relevancy"] > 0.85, "Off-topic answers!"

Context Adherence (2026 Metric)

NEW

Stricter than faithfulness. Decomposes output into atomic claims, then verifies EACH claim against EACH context chunk. Score = supported_claims / total_claims. Production standard is >0.95.

Groundedness Score

PRODUCTION

Binary per-sentence check: is this sentence grounded in the provided sources? Unlike faithfulness (0-1 aggregate), this shows you WHICH sentences hallucinated. Critical for debugging.

Context Retrieval Quality

RETRIEVER

Combines precision@k + recall + MRR (Mean Reciprocal Rank). Tells you: are the TOP chunks actually useful? Position matters — chunk at position 1 is weighted higher than position 5.

5. Safety & Guardrails — Runtime Defense Architecture

Guardrails are programmatic checks that sit between a model and the user (or downstream tool). They block, rewrite, or escalate unsafe responses in real time. In 2026, this is a runtime layer that scores every prompt and response across multiple risk categories.

8. Alignment — Making Models Do What We Want

By 2026, every frontier model ships with layered alignment: pretraining filters → supervised fine-tuning → RLHF/DPO → Constitutional AI → runtime safety classifiers. Understanding this stack is essential for both safety engineering and interview discussions.

RLHF (Reinforcement Learning from Human Feedback)

Process: Collect human rankings of model outputs → train reward model → use PPO to optimize policy against reward. Limitation: Expensive ($500K+ per round), reward hacking, need careful labeler calibration. Still the gold standard for frontier models.

DPO (Direct Preference Optimization)

Process: Skip the reward model entirely. Directly optimize the policy using preference pairs (chosen vs rejected). Advantage: Simpler, cheaper, more stable training. Used by Llama, Mistral, many open-source models. Limitation: Less flexible than RLHF for complex preferences.

Constitutional AI (Anthropic, 2023→2026)

Process: Define principles ("be helpful, honest, harmless"). Model generates → self-critiques → revises. Then RLAIF (RL from AI Feedback) using the constitution. Key insight: Reduces human labeling by letting the model judge itself against explicit rules. Claude's safety comes from this.

🎯 The Alignment Paradox (2026 Insight)

A foundation model trained with RLHF/DPO/CAI inherits a SINGLE calibrated policy — one point on the helpfulness-harmlessness frontier. But YOUR application might need a DIFFERENT point: a medical chatbot needs stricter safety than a creative writing assistant. This is why Layer 5 (runtime guardrails) exists — you customize the safety boundary for YOUR use-case without retraining the entire model.

🧠 Interview Deep-Dive Questions & Answers PREP

Q: How would you evaluate a RAG system in production?

A: Three layers. First, deterministic checks on every response: JSON validity, length bounds, PII scan. Second, embedding-based metrics on every response: RAGAS faithfulness and context precision — alert if they drop below threshold. Third, LLM-as-judge on a 10% sample: custom rubric scoring for domain-specific quality. Plus drift detection daily — track embedding distributions and alert on shift.

Q: What's the difference between faithfulness and hallucination?

A: Faithfulness measures "are all claims in the output supported by the provided context?" Hallucination is broader — includes fabricated facts even without context. In RAG systems, faithfulness is what matters: the model should ONLY say things grounded in retrieved chunks. A model can be non-hallucinating (factually correct from training) but unfaithful (making claims not in the provided context).

Q: How do you defend against prompt injection?

A: Three-layer defense. Architectural: privilege separation (the LLM has limited tool access, can't delete data). Runtime detection: input classifier scores every prompt for injection probability (Lakera Guard, NeMo). Output monitoring: check if the response leaked system prompt or executed unintended actions. Plus: sandboxing tool outputs, validating all MCP inputs, and running automated red-team suites in CI.

Q: Explain Constitutional AI.

A: Anthropic's approach to alignment without massive human labeling. You define a set of principles (the "constitution"). The model generates a response, then critiques itself against those principles, then revises. This self-improvement loop generates training data. Phase 1: SFT on self-revised outputs. Phase 2: RLAIF — the model acts as its own reward model using the constitution. Result: aligned models at 90% less human labeling cost.
