🧰 P0 — Tools, Function Calling, RAG & Memory

The four things that turn a chatbot into an agent that acts. Founder-level: how each works, where it breaks, and the cost/reliability tradeoffs.

⭐ THE FRAME

A model that only talks is a toy. The moment you give it tools (to act), function calling (to act reliably), RAG (to know your data), and memory (to persist), you've built something a company will pay for. These are the P0 "hands and brain" of an agent.

1. Function / Tool Calling — the professional way to act

Old way: parse free text like ACTION: search\nINPUT: ... → fragile regex hell. New way: the model returns structured JSON describing which function to call. The API enforces the schema.

TEXT PARSING (fragile) FUNCTION CALLING (robust) ┌────────────────────┐ ┌──────────────────────────┐ │ LLM text output │ │ LLM returns tool_call: │ │ "ACTION: search..." │ vs │ { name:"search", │ │ → regex → hope │ │ args:{"q":"AI jobs"} } │ │ → breaks on format │ │ → schema-validated JSON │ └────────────────────┘ └──────────────────────────┘ 
tools = [{
  "type":"function",
  "function":{
    "name":"search_jobs",
    "description":"Search job listings. Returns title, company, location.",
    "parameters":{
      "type":"object",
      "properties":{
        "query":{"type":"string","description":"what to search for"},
        "location":{"type":"string","description":"city or 'remote'"}
      },
      "required":["query"]
    }
  }
}]
resp = client.chat.completions.create(model=..., messages=msgs,
                                      tools=tools, tool_choice="auto")
call = resp.choices[0].message.tool_calls[0]
result = search_jobs(**json.loads(call.function.arguments))  # no regex!
Why it wins
Schema-enforced parsing (no regex)
Parallel tool calls in one turn
Built-in type + enum validation
Universal: OpenAI, Anthropic, Groq, Ollama — and the basis of MCP
Failure modes: hallucinated arguments, schema drift, weak models emitting invalid JSON. Fixes: strict enums, Pydantic/instructor validation, retry-on-invalid, and clear descriptions.
YOUR work: your MCP server exposes tools as structured functions — MCP is literally function calling + a transport layer. You've already built the infrastructure agents call.

2. Tool Integration — making the real world callable

A tool is any function the agent can invoke: API, DB query, web search, file I/O, code execution. Three properties separate hobby tools from production tools:

PropertyWhy it matters
IdempotencyIf the agent retries, it mustn't double-charge / double-post
TimeoutsA hung tool freezes the whole loop
Errors as observationsReturn a readable error so the agent can retry/skip, not crash
def search_jobs(query, location="remote"):
    try:
        r = httpx.get(API, params={...}, timeout=10)   # timeout!
        r.raise_for_status()
        rows = r.json()
        if not rows:
            return "No results. Try a broader query."    # error-as-observation
        return format(rows)
    except httpx.TimeoutException:
        return "Search timed out. The agent may retry or skip."
YOUR work: your groq_client.py (retry + fast-fail) and narration_generator.py (fallback ladder) already embody this. That fallback-chain instinct is exactly production tool design.

3. RAG for Agents — giving the agent YOUR data

Retrieval-Augmented Generation = fetch relevant chunks and put them in context so the model answers from your knowledge, not its training. For agents, retrieval is often just another tool the agent chooses to call.

4. Memory & State — short-term vs long-term

TypeWhatChallenge
Short-termconversation history, scratchpad, current run statecontext window overflow
Long-termpersisted facts/preferences across sessions (often in a vector DB)poisoning + stale data

Beating context overflow (the #1 memory bug)

  • Sliding window: keep the last N turns verbatim.
  • Summarization: periodically compress old history into a short summary — but don't lose key facts.
  • Observation compression: trim verbose tool results before feeding them back.
  • Typed state object: store structured fields, not raw transcript.
YOUR work: your PipelineState in utils/state.py is a typed state object — exactly the right pattern. LangGraph's checkpointer gives you resumable state for free.

5. Prompting for Agents (the cheap, high-leverage lever)

  • System prompt defines the agent's role, available tools, and output format.
  • Few-shot tool examples dramatically cut wrong-tool-selection errors.
  • Enforce output format explicitly (and prefer function calling to enforce it structurally).
  • Low temperature (~0.2) for stable, deterministic tool decisions.
Anthropic's lesson, applied: treat tool descriptions with as much care as the main prompt — write them like a docstring for a junior dev, with examples and edge cases. This single habit prevents most tool-selection failures.

6. Founder-Level Tradeoffs

LeverThe founder decision
How many tools?Fewer = cheaper, safer, less confusion. Add only what the task needs (also a security win).
RAG vs long context?RAG = cheaper + scoped; giant context = simpler but costly and can bury the needle.
Memory depth?Every remembered token is recurring cost. Summarize aggressively.
Text parse vs function calling?Always function calling in production — reliability compounds across millions of calls.

7. Q&A Drills

Why function calling over text parsing?
Schema-enforced structured output means no fragile regex, built-in type/enum validation, parallel tool calls, and it's universal across providers. In production, parsing reliability compounds — one brittle regex fails at scale.
How do you stop context overflow in a long-running agent?
Sliding window for recent turns, periodic summarization of old history, compressing verbose tool observations, and a typed state object instead of a raw transcript.
What makes a tool production-grade vs a demo tool?
Idempotency (safe to retry), timeouts (won't freeze the loop), and returning errors as readable observations so the agent can retry or skip instead of crashing.
Dense-only retrieval is missing exact matches like product IDs. Fix?
Add sparse/BM25 and fuse with dense via hybrid search (RRF), then rerank the top-k. Dense captures meaning; sparse captures exact terms.
